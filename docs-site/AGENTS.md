# Documentation writing

- Write task guides and references for people using csls.
- Describe supported behavior in direct, affirmative sentences, with concrete steps and examples.
- Lead with the user action or result. Describe one behavior at a time.
- State the enabling setting or prerequisite alongside the behavior it controls.
- Use plain descriptions and concrete examples. Remove corrective asides and self-evaluation.
- Keep development status, milestone progress, unfinished work, and unsupported-feature inventories out of site content.
- Explain each feature on its own terms. Avoid contrasting what it does with what it does not do.
- Express prerequisites, authorization, ownership, and safety requirements as clear instructions.
- Update generated reference wording at its source and regenerate the page.
